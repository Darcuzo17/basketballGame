# Баскетбольный менеджер: каркас проекта

Spring Boot 3, Vaadin Flow, PostgreSQL, Flyway, Maven. Java 21.

## Быстрый старт

1. Поднять базу и тестовую почту: `docker compose up -d`
2. Запустить приложение с демо-миром:
   `mvn spring-boot:run -Dspring-boot.run.profiles=dev`
   (при первом запуске Vaadin скачает Node и соберёт фронтенд, это займёт несколько минут)
3. Открыть http://localhost:8080, зарегистрироваться. Письмо подтверждения видно в Mailpit: http://localhost:8025
4. Тесты: `mvn test` (тесты с базой требуют запущенный Docker)
5. Сборка для продакшена: `mvn -Pproduction clean package`

Без профиля `dev` демо-мир не создаётся: шаблон мира пуст, и экран выбора клуба покажет пустую карту.

## Как устроен старт игры

- Мир (города, клубы, игроки, спонсоры) хранится в **шаблоне**: это сохранение с `is_template = TRUE` без владельца.
- Кнопка «Начать играть» вызывает `GameStartService`: создаёт сохранение игрока и одной транзакцией
  копирует в него мир функцией `clone_world` (миграция V2). При ошибке не остаётся ни пустого сохранения, ни полукопии.
- Расписание, таблицы и матчи в шаблон не входят: их создаёт `ScheduleService` сразу после копирования мира.

## Как считается игровой день

`DaySimulationService` проходит шаги по порядку `order()`, весь день одной транзакцией:

| order | шаг | что делает |
|---|---|---|
| 10 | `SeasonPhaseStep` | в день первого матча переводит сезон из межсезонья в регулярный чемпионат |
| 20 | `RecoveryStep` | снижает усталость игроков |
| 50 | `MatchDayStep` | играет все матчи дня (счёт, четверти, хроника, таблица, усталость); для матчей клуба игрока создаёт событие |
| 90 | `SeasonEndStep` | когда сыграны все матчи, завершает сезон и сообщает итоговое место |

Расписание: двухкруговой турнир в каждой лиге, один тур в неделю, матчи по субботам и воскресеньям,
первая суббота после 1 октября. Результат матча зависит от силы команд (восемь лучших игроков и навык тренера),
домашнего поля и случайности; одинаковый матч всегда даёт одинаковый счёт. Режим «до события» считает дни по одному
и останавливается на матче клуба игрока, на конце сезона или через 400 дней без событий.

## Структура

- `ru.bbmanager.account`: пользователи, регистрация, подтверждение email, текущий пользователь
- `ru.bbmanager.game`: сохранения, старт новой игры
- `ru.bbmanager.club`: каталог клубов для экрана выбора (из шаблона мира)
- `ru.bbmanager.competition`: расписание, расчёт матча, запросы для экранов чемпионата
- `ru.bbmanager.simulation`: расчёт игрового дня; `simulation/step`: шаги дня (каждая механика отдельным бином SimulationStep)
- `ru.bbmanager.config`: безопасность, настройки
- `ru.bbmanager.ui`: экраны Vaadin; `ui/map`: Java-обёртка карты
- `frontend/components`: `russia-map.js` (компонент карты), `russia-outline.js` (контур и проекция, генерируется)
- `src/main/resources/db/migration`: миграции Flyway; `db/dev`: демо-мир
- `tools/outline`: как пересобрать контур; `tools/map-test`: проверка карты в jsdom (`./run.sh`)

## Карта

Границы России и проекция посчитаны заранее, тайловый сервер не нужен. Поддерживаются колесо мыши,
перетаскивание, щипок на телефоне и кнопки масштаба. Город с несколькими клубами показывается одним
маркером со счётчиком, по клику открывается список клубов города.

## Что проверено, а что нет

- Проверено на PostgreSQL 16: все миграции (V1, V2, V3 и демо-мир), копирование мира (числа записей совпадают
  с шаблоном, ссылки не ведут в шаблон или чужую партию, партии независимы, ошибки откатывают транзакцию,
  второй шаблон создать нельзя).
- Проверено: полный сезон на PostgreSQL 16 по SQL-запросам, извлечённым из Java-кода (расписание, шаги дня,
  запросы экранов): сыграны все матчи, таблицы сходятся (победы равны поражениям, забитые очки равны пропущенным),
  конец сезона и события работают, дубль чемпионата отклоняется.
- Чистая логика (круговой турнир, расписание, расчёт матча) прогнана тестами JUnit через заглушку без Spring: 15 тестов.
  Расчёт матча проверен на 100 тысячах игр: у равных команд хозяева выигрывают около 60%, при разнице сил 13 пунктов сильный дома около 90%.
- Компонент карты проверен в jsdom (`tools/map-test/run.sh`).
- Spring- и Vaadin-код в среде подготовки не компилировался (не было доступа к Maven Central) и в браузере
  не запускался. При первой сборке возможны мелкие правки импортов и API под вашу версию Vaadin.
- Версии Spring Boot и Vaadin в pom.xml стоят как заглушки: проверьте актуальные совместимые версии и условия
  лицензий платных компонентов. В новых версиях `VaadinWebSecurity` может быть заменён на `VaadinSecurityConfigurer`.
- Значения в V3 (лиги, правила, требования) примерные и требуют уточнения. Параметры расчёта матча (база очков, домашнее поле, влияние силы) лежат константами в `MatchSimulator` и подбираются при балансировке.
